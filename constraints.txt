# VERIS — every package an install resolves to, PINNED.
#
# requirements.txt pins what VERIS asks for directly. Those packages pull in others,
# and a package nobody pinned resolves to whatever is newest on the day `pip install`
# runs. That breaks two promises at once: that the build which passes today still
# passes on demo day, and that THIRD_PARTY_NOTICES.md — which records the version of
# every package it lists — describes what a fresh install actually ships.
#
# So this file pins the whole closure: the runtime requirements and everything they
# depend on, then the development tools and everything they depend on. A constraint
# only fixes the version of a package that something else requires; it never installs
# anything by itself. requirements.txt applies this file (`-c constraints.txt`), so the
# plain `pip install -r requirements.txt` that README, CI and any image build use
# installs exactly these versions.
#
# tests/test_licensing_and_branding.py fails if a package in the installed closure has
# no pin here (and names the line to add), if a pin here is for a package nothing
# needs, if a pin disagrees with requirements.txt or pyproject.toml, or if
# THIRD_PARTY_NOTICES.md records a different version.
#
# To change a version: edit the pin here (and in requirements.txt and pyproject.toml
# for a direct dependency), reinstall, run the suite, regenerate the notices, commit.
